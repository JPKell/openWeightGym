System → Backups backs up both machines at once. Each machine archives every store it is configured with, and the set is verified only when both halves are: SQLite stores are copied with SQLite's online backup and checked for integrity, and PostgreSQL stores are dumped with pg_dump, restored into a temporary database and compared with the source. A configured store that is missing or does not answer stops the set rather than leaving it quietly incomplete.

Choose how many sets each machine keeps; older ones are removed after a backup succeeds, and zero keeps them all. Restore preview shows what a set would change before anything is restored. Restoring needs a maintenance window: stop the services that use the stores first.

{% endcall %} {% call doc_section('What a set leaves out', 'excluded') %}

Archives stay on the machine that made them, readable only by its service account, and are not offered as browser downloads.

The accounts store holds the password verifiers and authenticator secrets needed to recover accounts. Raw API keys, provider keys, key folders, environment files, runtime command-line tokens and the console's cookie-signing secret are not included: recover them separately from where you keep them. Model weights are not included either; the compute manifest records each model's identity, path, size, known SHA-256 and likely Hugging Face source.

{% endcall %} {% call doc_section('Keeping identities through a reinstall', 'identities') %}

Run suite-identity in a terminal on each host to export a passphrase-encrypted bundle of accounts, permissions, service credentials and configuration. Request and conversation history is not included. Stop the services that take part before exporting or importing. An import previews its changes first and refuses to replace different existing accounts. The identity export and import reference has the details.
