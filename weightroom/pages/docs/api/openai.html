Tool definitions, choices and tool history in any model request require the account’s use-tools ability. This applies to local, role, cloud and batch requests; missing permission returns 403 tools_not_allowed. Existing groups receive the ability once on upgrade. Per-account overrides and app-session intersections apply. ToolLocker access is controlled separately by tool patterns.

Responses MCP tools use {"type":"mcp","server_label":"toollocker"}. Only this control node’s /mcp or /mcp/{toolset} is available; foreign URLs are refused. allowed_tools only narrows the caller’s tools. Calls use the caller’s key and one shared trace, with permission checked again for every call. require_approval defaults to never; always and named-tool filters pause with an mcp_approval_request. Continue its stored response with mcp_approval_response, approval_request_id and approve. Approval mode requires store:true; server tools require logging. Client functions and MCP tools may be mixed. All MCP content parts and error details are retained; only the model-facing copy is bounded to 64 KiB. A result that raises sensitivity stops a subsequent cloud request with tool_result_too_sensitive. Administrators can edit the default 25-call / 900-second limits under Settings → Tools; exhausted runs end incomplete with max_tool_calls or max_tool_time. MCP listing, argument and result events stream alongside model output.

Stored Responses are available under Logs → Model activity → Responses. Records are scoped by stable account identity and current sensitivity clearance; account deletion removes them. Each account can keep at most 10,000 responses or 256 MiB. The console provides filters, pagination, chain navigation, ordinary request links and JSON export.

openWeightGym batch endpoints are /v1/chat/completions, /v1/responses, /v1/completions, /v1/embeddings, /v1/rerank, /v1/images/generations, /v1/images/edits and the custom /v1/audio/generations. MCP tools are refused per batch line; client function tools are allowed. Responses batch lines default to store:false and must omit stream and previous_response_id; store:true is a per-line error. Chat and Responses lines may share a file, with each line retaining its endpoint. Other OpenAI batch endpoint choices are not implemented. See the official Batch API for the upstream contract; openWeightGym's narrower list above is authoritative here.

The worker registers a broad POST /v1/{path} inference proxy. A backend may accept an additional POST with a model field; that is backend-dependent passthrough, not an openWeightGym implementation or a compatibility promise. Unknown requests need not return 404: model validation or an engine refusal can happen first. Hosted forwarding likewise does not implement OpenAI resources locally.
